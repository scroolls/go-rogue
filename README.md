# Rogue Go

Пошаговая roguelike-игра для терминала: процедурные подземелья, бои, инвентарь, сохранение прогресса и таблица результатов. Цель — пройти 21 уровень.

School 21. Командный учебный проект, три участника. Реализация разделена на игровую логику, хранение данных и терминальный интерфейс.

## Возможности

- Девять комнат на каждом уровне, соединённых коридорами.
- Шесть типов противников, оружие, еда, эликсиры и свитки.
- Туман войны, цветные двери и ключи, проверка доступности выхода.
- Корректировка сложности по результатам прохождения.
- Основной 2D-вид и дополнительный ray-casting вид с мини-картой.
- JSON-сохранения и таблица результатов с сортировкой по сокровищам и глубине.

Стек: Go, tcell v2, JSON, `testing`. Для проверки связности используется BFS, для видимости — алгоритм Брезенхэма, для дополнительного вида — ray casting.

## Запуск

Требуется Go 1.22 или новее и интерактивный терминал. Проверено на Go 1.25.4. Рекомендуемый размер окна — от 120 столбцов и 35 строк. Интерфейс на русском языке; команды вводятся в английской раскладке.

Из корня репозитория:

```sh
go mod download
go run .
```

Для сборки в Windows:

```powershell
go build -o bin/rogue.exe .
.\bin\rogue.exe
```

Для Linux/macOS:

```sh
go build -o bin/rogue .
./bin/rogue
```

## Управление

| Клавиша | Действие |
| --- | --- |
| `N` / `R` в меню | Новая игра / загрузка сохранения |
| `W A S D` | Перемещение; движение во врага — атака |
| `H` / `J` / `K` / `E` | Оружие / еда / эликсиры / свитки |
| `1`–`9` в инвентаре | Выбрать предмет |
| `0` в разделе оружия | Убрать оружие в рюкзак |
| `Esc` в инвентаре | Отменить выбор |
| `V` | Переключить 2D/3D |
| `W` / `S` в 3D | Вперёд / назад |
| `A` / `D` в 3D | Поворот |
| `P` | Сохранить |
| `L` | Таблица результатов |
| `Q` / `Esc` в игре | Сохранить и выйти |

При переходе на следующий уровень игра сохраняется автоматически. Сохранения создаются в `data/save.json`, результаты — в `data/scoreboard.json`, относительно текущей рабочей папки. Эти файлы исключены из Git. Для продолжения запускайте игру из той же папки.

## Устройство

```text
main.go
internal/
  domain/         генерация, модели, перемещение, бой, инвентарь
  datalayer/      чтение и запись JSON, сортировка результатов
  presentation/   tcell, ввод с клавиатуры, 2D/3D-отрисовка
```

Domain не зависит от терминала и файловой системы. Presentation вызывает игровую логику и сохраняет её состояние через datalayer. Перед заменой файла сохранение полностью записывается во временный файл; ошибки чтения и записи передаются в интерфейс.

## Проверки

```sh
go test ./...
go vet ./...
go build ./...
go test -race ./...
```

Тесты покрывают связность комнат, двери и ключи, инвентарь, бой, адаптацию сложности, сохранение и восстановление состояния, повреждённые сохранения и сортировку результатов. Терминальный интерфейс проверяется через `tcell.SimulationScreen`: символ игрока, кириллица, переключение вида, сохранение и выход.

Автоматическая проверка экрана не заменяет ручное прохождение игры. `-race` требует CGO и C-компилятор; в использованном Windows-окружении он недоступен.

## Командная работа

Проект выполнен командой из трёх человек. Мой вклад в совместную разработку — работа над слоем данных: JSON-сохранения и восстановление игровой сессии, хранение и сортировка результатов, тесты сохранений.

## Ограничения

Игра использует один слот сохранения и локальные JSON-файлы. Одновременный запуск нескольких экземпляров с общей папкой `data` не поддерживается. 3D-режим — дополнительная визуализация той же пошаговой игры. Поддержка терминалов зависит от tcell; запуск из панели вывода редактора без интерактивного терминала не подходит.
